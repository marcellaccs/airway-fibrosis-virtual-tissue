## Decisions

- **Epithelial y-band is now derived from cell size, not hardcoded** (Marcella's call, 2026-09-18). With the band left at its old fixed 6 rows (y = 74–79) and cell height 8, every epithelial cell seeded 16 px under its 64 px target and relaxed into the open lumen: narrowing was **−7.9% by MCS 100 and −12.5% by MCS 1000**, vs −0.3% / −1.5% for the unrescaled baseline. That is cell-body inflation, not ECM-driven displacement.
  - `parameters.py` now defines `LUMEN_ROWS = 20`, `LUMEN_MIN_Y = DOMAIN_Y − LUMEN_ROWS` (80), `EPITHELIAL_Y_MAX = LUMEN_MIN_Y − 1` (79), `EPITHELIAL_Y_MIN = EPITHELIAL_Y_MAX − EPITHELIAL_CELL_HEIGHT + 1` (**72**), `SUBEPITHELIAL_Y_MAX = EPITHELIAL_Y_MIN − 1` (**71**), and `TARGET_VOLUME_EPITHELIAL = WIDTH × HEIGHT`. `EPITHELIAL_CELL_WIDTH/HEIGHT` moved above the geometry block so it can use them.
  - **Anchor choice:** the lumen (y = 80–99, 4000 px) stays fixed so narrowing percentages remain comparable with earlier runs; the subepithelial band absorbs the 2 rows (70 → 68 rows, y = 4–71). Side effect: bulk subepithelial occupancy denominators are now 13,600 px, not 14,000, and the "70 px / 87.5 µm" subepithelial-band figure in `citation_todo.md` (Eapen2021 item) is now 68 px / 85 µm.
  - The alternative Marcella raised (using CC3D's XML initializer for the epithelial layer) was not taken: it would mean rebuilding how per-cell state and FPP links are attached. Still available if the Python seeding gets awkward.

### Seed fix (2026-09-20, commit `b7530f6`)

`TissueInitializationSteppable.seed_python_rng()` now seeds Python's `random` (unseeded until now: fibroblast placement, damage seeding, recruitment) so that the XML `<RandomSeed>` is the only knob. `Simulator.getRandomSeed()` returns the pinned value, or **0 when the XML has no `<RandomSeed>`**. Pinned: `random.seed(seed)`. Unpinned: `random.seed()` from OS entropy, *not* 0. Every log opens with a banner saying `PINNED in XML` or `none pinned, this is a random run`, so a forgotten pin shows in the first lines. The committed XML has no `<RandomSeed>`; general runs stay random.

- First version seeded Python with `getRandomSeed()` unconditionally, i.e. with 0 on every unpinned run, which would have fixed the Python-side randomness in exactly the runs meant to stay random. Caught by the check, fixed before the commit.
- Check (3000 MCS, scratch copies): two runs pinned to seed 7 gave **identical** output (256 diagnostic lines, −5.2% narrowing in both). Three unpinned runs drew different entropy seeds and gave different results (−6.5%, −7.8%, −7.1%). No tracebacks in any.
- Limits: unpinned runs cannot be reproduced afterwards, because CC3D's own seed is not recoverable from a run that started unpinned. The unpinned check shows different outcomes, but the distinct logged Python seeds are the direct evidence for the Python side (the MCS-0 diagnostic line only shows counts, not placement).
- Reproducing an old result needs the seed at the start: pin it, run, keep the log.

### Live-footprint containment check (2026-09-22)

`check_sheet_integrity`'s "mesenchymal cells with COM inside epithelial band" compared each
mesenchymal cell's yCOM to the *fixed* `p.EPITHELIAL_Y_MIN..MAX` initialization band, so once the
sheet genuinely moves the band no longer describes where the sheet is -- exactly the ambiguity
`flood_fill_lumen_pixels` was already written to avoid for the lumen. Replaced with
`compute_epithelial_column_bounds()`: per-x-column (min_y, max_y) of pixels the sheet actually
occupies *now*, built from `get_cell_pixel_list` the same way `_count_pixel_components` reads
pixels. A mesenchymal cell counts only if one of its own pixels falls inside the sheet's current
column-local y-span -- genuine overlap, not proximity to where the sheet used to be.

**Verified directly against the isolation run's config C, seed 13** (identical config and seed,
so an exact trace match -- same −8.2% narrowing at MCS 3000 confirms it): old check read 0 → 6 → 8
(MCS 0/1000/3000) with sheet integrity clean the whole time; new check reads **0 → 0 → 0** on the
same run. Confirms the nonzero counts really were the vacated-space false positive, not intrusion.
