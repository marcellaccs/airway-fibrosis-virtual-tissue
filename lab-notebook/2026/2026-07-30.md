# 2026-07-30

**Focus:** Debug a "plot window won't open" symptom on a CC3D practice model, and use it to pin down where CC3D actually writes outputs — the record-keeping question from repo setup.

## Did
- Debugged a practice model (`Celldivision`, in the separate CC3D scratch folder, not this
  repo): the average-volume plot window would not open in the Player.
- Ran the model headless with CC3D's bundled Python to isolate code vs. GUI: all three
  steppables executed across 100k MCS with **zero Python errors**, and the plot API calls
  (`add_new_plot_window`/`add_plot`/`add_data_point`) ran clean — so it was not a steppable bug.
- Confirmed root cause = stale Player layout in `Simulation/_settings.sqlite` (window
  remembered as closed/off-screen). Deleting/resetting it restored the window. This fix was
  already documented here in `CLAUDE.md` and `model/cc3d/README.md`.
- Audited this repo for the same class of problem and found the "where to run" issue concretely.

## Decisions
- **Always run CC3D with `--output-dir results/cc3d/<run-name>`.** Documented in `CLAUDE.md`
  under CompuCell3D. A bare `run_script` call is the source of the stray output dumps below.
- Treat `_settings.sqlite` as disposable per-machine Player state (first suspect for any
  window/display glitch that isn't a code error); keep it gitignored (already is).

```
# Headless reproduction (bundled interpreter, practice model)

# Repo audit
git status --short          # two untracked *_cc3d_<timestamp>/ dumps, NOT ignored

```

## Results / observations
- **CC3D writes outputs into the current working directory when `--output-dir` is omitted**,
  as a timestamped `<project>_cc3d_<date>_<hash>/` folder. This is why the practice folder
  fills with `*_cc3d_*` dirs, and why two such dumps are sitting in this repo:
  - `M1_M2_antimony_cc3d_07_10_2026_19_28_01_be9b19/` (repo root — run launched from root)
  - `model/cc3d/M1_M2_antimony_cc3d_07_10_2026_09_37_52_55459e/` (run launched from `model/cc3d/`)
- Neither matches a `.gitignore` rule (`.gitignore` only ignores `results/*`), so both are
  untracked and would be swept into the next `git add` — the exact record-keeping risk raised
  at repo setup.
- `model/cc3d/README.md` step 4 teaches the bare command without `--output-dir`, which is what
  produces these dumps; it should be updated to the `results/` form.
